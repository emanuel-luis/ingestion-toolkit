# ingestion-toolkit

Public MIT Python CLI (`ingest`) that writes validated ingestion configs for relational sources.
Design: `docs/REFACTOR_PLAN.md`; decisions: `docs/DECISIONS.md`.

## Commands

```bash
uv sync                        # install (use --locked in CI)
uv run ruff check              # lint
uv run ruff format --check     # format check (drop --check to fix)
uv run mypy                    # strict, pydantic plugin, src only
uv run pytest                  # tests, derandomized Hypothesis profile
make install lint test         # the same through make
uv build                       # sdist and wheel
```

On this machine `python3` is a stub: use `uv run`.

## Repo map

- `src/ingestion_toolkit/models/config.py`: frozen config models and every validator.
- `src/ingestion_toolkit/config_io.py`: discover, read (collects all errors), write.
- `src/ingestion_toolkit/cli/`: `main.py` (app, `--version`), `add.py`, `validate.py`, `_report.py`.
- `naming.py`, `cron.py`, `columns.py`, `errors.py`: small pure helpers.
- `examples/postgres/`: configs generated by `ingest add`; `tests/test_examples.py` rebuilds them.
- `tests/strategies.py`: Hypothesis strategy for valid config dicts.

## Invariants

- The CLI never imports Airflow.
- Written configs are deterministic: model field order, None fields omitted (except
  `schedule.cron: null`), no timestamps, LF line ends.
- Changing a config field cascades to the model, the CLI options in `add.py`, `config_io.py`,
  the tests, `examples/` and the README config reference. `tests/test_examples.py` fails when the
  examples or the README YAML drift.
- Defaults live in the models only; the CLI passes just the options the user gave.
- Python floor is 3.11: no 3.12+ syntax.

## Conventions

- Line length 100, ruff with `BLE`, mypy strict. A broad `except` needs `# noqa: BLE001 - reason`.
- `from __future__ import annotations` in every module, pathlib only, docstrings on public API.
- Validation messages end with `Fix: <hint>`. CLI error line:
  `error: <path>: <loc>: <message>. Fix: <hint>`, then `N valid, M invalid`.
  Exit codes: 0 ok, 1 invalid config or refused overwrite, 2 usage.
- Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`).
- Generic names only (source erp, tables orders and customers). Never copy employer code.
