# ingestion-toolkit

Public MIT Python CLI (`ingest`) that writes validated ingestion configs for relational sources
and renders them into self-contained Airflow 3 DAG files.
Design: `docs/REFACTOR_PLAN.md`; decisions: `docs/DECISIONS.md`.

## Commands

```bash
uv sync                        # install (use --locked in CI)
uv run ruff check              # lint
uv run ruff format --check     # format check (drop --check to fix)
uv run mypy                    # strict, pydantic plugin, src only
uv run pytest                  # tests, derandomized Hypothesis profile (slow ones excluded)
uv run pytest -m slow          # the render property test
uv run pytest tests/test_golden.py --update-golden   # rewrite goldens, then read the diff
make render                    # render examples/postgres into output/
make install lint test         # the same through make
uv build                       # sdist and wheel
make d2-install                # once, Linux or WSL: D2 v0.9.0 pinned by sha256
make diagrams                  # render docs/diagrams/*.d2 to .svg (commit both)
make diagrams-check            # what the CI job diagrams runs: render, fail on any SVG diff
make diagrams-watch NAME=architecture   # live preview while editing one diagram
```

On this machine `python3` is a stub: use `uv run`.

## Repo map

- `src/ingestion_toolkit/models/config.py`: frozen config models and every validator.
- `src/ingestion_toolkit/config_io.py`: discover, read (collects all errors), write.
- `src/ingestion_toolkit/cli/`: `main.py` (app, `--version`), `add.py` (rdbms and mssql), `init.py`,
  `validate.py`, `render.py`, `_report.py`. `scaffold/`: the starter config `init` writes.
- `src/ingestion_toolkit/renderer.py`: Jinja environment, `build_dag_context`, `py` filter, atomic
  write, all-or-nothing `render_all`. `models/task.py`: the frozen contexts templates read.
- `src/ingestion_toolkit/sql.py`: quoting and the SQL text. `templates/`: the DAG file, split into
  `constants`, `helpers/`, `tasks/`; design in `docs/generated-dags.md`.
- `scripts/check_dag_imports.py`: DagBag gate (needs Airflow; CI job `dag-import`, WSL locally).
- `naming.py`, `cron.py`, `columns.py`, `errors.py`: small pure helpers.
- `examples/postgres/`, `examples/mssql/`: configs generated by `ingest add`; `tests/test_examples.py`
  rebuilds them. `docs/cdc-contract.md`: what a CDC source must provide.
- `tests/test_generated_helpers.py` runs the pure helpers of a rendered DAG without Airflow.
- `tests/strategies.py`: Hypothesis strategy for valid config dicts. `tests/golden/`: rendered
  DAGs of the examples.
- `docs/diagrams/`: D2 sources and their committed SVGs (architecture, data-flow,
  data-flow-patterns, data-model, user-flows-*), all importing `_style.d2` (ELK, light and dark
  themes, one class per element kind). Edit `.d2` files with an editor, not sed or a script over
  stdin (they mangle `\n` and `·`), then `make diagrams` in WSL. Keep each under ~1,300 px wide
  and ~25 nodes; no Mermaid in the repo. A diagram mirrors the code: update it when the
  templates, the ops DDL, the CLI commands or the CI jobs it shows change.

## Invariants

- The CLI never imports Airflow.
- Templates contain no logic: only `include`, `for` and `| py`. The renderer picks template names
  and `sql.py` builds every SQL string; identifiers are quoted there, literals go through `py`.
- Goldens change only through `--update-golden`, never by hand. Generated code must parse, pass
  `ruff check` and be `ruff format` clean (the `py` filter lays literals out like ruff).
- Rendered DAGs run on Python 3.10+ (no `datetime.UTC`) and use only imports Airflow 3.3.2 does
  not deprecate; `check_dag_imports.py` fails on warnings from DAG files.
- Written configs are deterministic: model field order, None fields omitted (except
  `schedule.cron: null`), no timestamps, LF line ends.
- Changing a config field cascades to the model, the CLI options in `add.py`, `config_io.py`,
  the tests, `examples/` and the README config reference. `tests/test_examples.py` fails when the
  examples or the README YAML drift.
- Defaults live in the models only; the CLI passes just the options the user gave.
- Python floor is 3.11: no 3.12+ syntax.

## Conventions

- Line length 100, ruff with `BLE`, mypy strict. A broad `except` needs `# noqa: BLE001 - reason`.
- `from __future__ import annotations` in every module, pathlib only, docstrings on public API.
- Validation messages end with `Fix: <hint>`. CLI error line:
  `error: <path>: <loc>: <message>. Fix: <hint>`, then `N valid, M invalid`.
  Exit codes: 0 ok, 1 invalid config or refused overwrite, 2 usage.
- Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`).
- Generic names only (source erp, tables orders and customers). Never copy employer code.
